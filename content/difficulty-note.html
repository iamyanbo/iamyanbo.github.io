Research note / Camera–LiDAR fusion

DifficultyPainting

Point painting transfers information from a 2D image into a 3D point cloud. Using the camera calibration, we project each LiDAR point into the image and attach the features at that pixel to the point. A 3D detector can then use image information alongside the point’s spatial coordinates.

DifficultyPainting applies this idea to detection difficulty. A distant, partly occluded object may be difficult to recognise even when its location is known; the image helps estimate that difficulty before the estimate is painted onto the points.

From an image to a difficulty estimate

The training target is one minus the 2D intersection-over-union between a projected detection and its matched image-space ground-truth box. A ResNet-18 predicts this difficulty from a 64 × 64 image crop, the object’s depth, and its box dimensions. The estimate is projected onto LiDAR points as an additional feature.

The detector aggregates these features into its bird’s-eye-view representation. During training, difficult examples receive more weight; at inference, the estimate adjusts detection confidence. These are separate uses of the same signal, rather than an independently demonstrated guarantee of calibration.

The main change is pedestrian detection: +8.78 AP for PointPillars and +5.81 for SECOND against each backbone’s stronger prior run. Cyclist AP also rises, while car AP falls by 1.28 and 0.13 points. Against the no-entropy baseline alone, the mean increases are +4.25 and +2.34 points; against the entropy variant, they are +3.51 and +3.43.

What the comparison establishes

DifficultyPainting has higher reported mean AP than both earlier variants on both backbones. This compares the complete configurations. It does not establish how much of the change comes from the difficulty feature, loss weighting, or confidence adjustment individually.

The published model configs use 80 epochs, batch size 4, and learning rate 0.003. However, the earlier baselines use 25 or 26 input features and enable database sampling; DifficultyPainting uses five input features and disables database sampling. UncertaintyPainting documents 5,979 training and 1,497 validation samples. The DifficultyPainting result tables do not include the evaluated sample IDs, so identical validation membership is not independently verified.

To isolate the difficulty signal, the next comparison needs the same training and validation IDs, augmentation, and training schedule, with each difficulty component toggled separately.

Difficulty-predictor input ablation

The difficulty predictor has its own evaluation. The following figures are reported correlations with the difficulty target, expressed as percentages; they are not detector AP.

Predictor inputsCorrelation (%)
Image only64.3

Image + box dimensions71.5
Image + depth + box dimensions89.0
All features, including truncation and occlusion85.3

The image, depth, and box-size combination had the highest reported correlation. Adding the annotation-level truncation and occlusion inputs did not improve it.

A related ablation: uncertainty

In UncertaintyPainting, I asked whether semantic entropy helps when appended to camera-painted LiDAR features. With the same rich semantic features, adding entropy changed moderate mAP from 75.78 to 76.52 for PointPillars, but from 80.17 to 79.08 for SECOND.

The mixed outcome is useful: uncertainty is not automatically useful just because we can measure it. These are separate experiments, rather than a controlled comparison between entropy and difficulty.
