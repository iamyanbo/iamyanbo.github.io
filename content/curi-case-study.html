What I built

My contribution is the runtime and the research process it makes inspectable. I designed the loop connecting literature intake, experiment proposals, execution, independent checks, and interpretation. I implemented the admission gates, persistent record, per-call cost metering, pause behaviour, and optional public mirror.

The agents implement and run individual experiments. Their generated experiment code and findings are outputs of that system; they are separate from my work on its design, implementation, and operating constraints.

The runtime uses TypeScript and Genkit, keeps local research state in SQLite, and runs experiments in separate Git worktrees. Firestore and Cloud Run provide an optional read-only mirror. The published implementation is open source under the MIT licence.

A question has to survive the loop

The watcher admits relevant prior work. The orchestrator selects a question and proposes a study. Before execution, a gate checks that the proposal cites existing evidence and does not merely repeat an earlier experiment. A refusal returns to the orchestrator with its reason.

The executor implements the admitted study in a separate worktree. The runtime reruns the decisive checks rather than relying only on the executor’s report. Findings name the conditions tested and retain their verdicts: supported, bounded, refuted, or inconclusive. Later evidence can supersede a synthesis while leaving the earlier account available.

I kept experiments on local hardware and made cloud publication optional. An early timing measurement recorded 3,442 seconds in tools against 5,695 seconds waiting for the model. A larger rented GPU would not remove that bottleneck; local execution also makes the tested hardware and data explicit.

The attention direction ran for about 43 hours and recorded 12 supported, 3 bounded, 1 refuted, and 1 inconclusive outcome. The second direction ran for about 11 hours in a different domain. These runs exercise the process; they do not validate it for every research problem.

A bounded negative result

An attention study expected cumulative-attention cache retention to degrade gracefully. At half the cache budget, it instead recorded 0% non-local needle retrieval, matching the random-eviction control. That comparison matters: failure without a control would tell us little about the retention policy.

The study used three samples on a 0.5B model and retained a bounded verdict. It measures retrieval failure; it does not distinguish a fact being evicted from a retained fact becoming unusable. The broader attention direction used 0.5B–1.5B models at context lengths up to 4,096 on one consumer GPU.

Reproduction rather than novelty

Other studies recorded slower speculative decoding despite 38–54% acceptance, and different sensitivity to key and value quantization. These behaviours are already described in the literature. The useful demonstration is that the process recovered them through experiments and kept the unsuccessful hypotheses, rather than claiming new mechanisms.

The strategy direction remains provisional. Its result files contain an unresolved discrepancy, and its withheld decade has not been evaluated. I would not present those figures as validated trading results.

What broke, and what I changed

Activity was keeping an idle agent awake

The supervisor resumed paused research on a timer. The agent restated its synthesis, that event reset the backoff, and the loop paid to reconsider the same evidence. Duplicate checks moved the activity between different kinds of record without removing its cause.

I changed the scheduler so that a pause stands until evidence arrives that could change the question. The documented follow-up measurement reduced quiet-hour cost from about $2.00 to $0.17. That is a measured operational change in this run, not a universal cost guarantee.

The first cost counter missed most of the calls

Counting only the final model call of a turn undercounted input tokens by roughly 20× and output tokens by 90×. Tool loops resend conversation context, and reasoning usage arrives separately. I moved metering into model middleware so every call contributes to the budget.

The record needed an enforceable publication boundary

I implemented redaction followed by an assembled-record check against local identifiers and credential values. A remaining match refuses publication; a withheld trace step remains visibly marked. The mirror exposes a read-only record rather than runtime controls.

One issue remained unresolved in the report: provider rate limits could exhaust a task’s attempts before an experiment ran. Twenty-two of the 125 attention runs failed, mostly because of provider or transport errors. Those failures should remain distinguishable from a scientific result.

Implementation decisions and postmortem ↗

How to inspect and reproduce it

Start with the public attention record: follow a task from its question and brief to its checks, outcome, and synthesis. The run report gives the hardware, experiment bounds, and unresolved issues; the build story explains the runtime decisions.

To run the system locally, follow the repository’s setup instructions, configure your own model provider, then run its doctor, environment preflight, and tests. Initialize an attention direction with domains/attention.domain.json, set a spend ceiling, and start the supervisor and watcher. Cloud publication is optional.

npx tsx src/cli.ts doctor
npm test
npm run typecheck
npx tsx src/cli.ts research preflight --refresh
npx tsx src/cli.ts research budget --max 40

A fresh agent run need not produce an identical sequence of studies. Reproducing the runtime’s behaviour means checking its admission, verification, recording, and publication invariants. Reproducing a finding means rerunning that study’s exact experiment and evaluator under its recorded conditions.

What I would test next

The next question is whether this process can produce a finding beyond the existing literature. That needs stronger replication, larger experiments where the question requires them, and a clear boundary between a new result and a new implementation of a known result. The current evidence supports a working, inspectable research runtime and bounded reproductions.
